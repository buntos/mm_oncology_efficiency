# Навчальний бюджет патчів у гістопатологічній класифікації раку легень

Матеріали експерименту до статті «Скорочення навчального бюджету патчів у гістопатологічній класифікації раку легень: якість, витрати відеопам’яті та повний час навчання».

Дослідження порівнює використання 16, 32 і 64 патчів на пацієнта за навчальну епоху. Під час валідації та тестування кожна модель отримує всі 64 патчі. Оцінюються якість класифікації, час навчання та використання пам’яті.

## Швидка перевірка опублікованих результатів без GPU

Для перерахунку метрик, парних довірчих інтервалів і перевірки ресурсних підсумків достатньо Python 3.10 або новішого та NumPy. Ваги моделей і зображення не потрібні.

```powershell
python -m pip install numpy
python -B tools/verify_published_results.py
```

Команда нічого не записує. Вона перевіряє хеші зафіксованих входів, відповідність прогнозів тестовому поділу, метрики дев’яти моделей, 10 000 парних bootstrap-повторів та ресурсні підсумки. Використовуються статистичні функції незміненого Stage 32: це перевірка повторного аналізу збережених прогнозів, а не незалежна реалізація метрик або повторний інференс.

## Склад публічної копії

Дев’ять вибраних моделей доступні в архіві
[selected_models.zip](https://github.com/buntos/mm_oncology_efficiency/releases/download/v1.0.0/selected_models.zip)
у [релізі v1.0.0](https://github.com/buntos/mm_oncology_efficiency/releases/tag/v1.0.0).
Архів потрібно розпакувати в корінь репозиторію зі збереженням структури папок.

Історичні команди навчання нижче потребують відновлення зовнішніх входів. Завершені результати є архівним знімком; повноцінний запуск на іншому комп’ютері ще не перевірений. Скрипт `23_cleanup_preprocessing_dev_outputs.py` належить до історії розробки й не є кроком відтворення статті.

## Дизайн експерименту

| Параметр | Значення |
|---|---|
| Дані | Гістопатологічні зображення TCGA-LUAD і TCGA-LUSC |
| Класи | Аденокарцинома та плоскоклітинний рак легень |
| Фінальна когорта | 929 пацієнтів: 455 LUAD і 474 LUSC |
| Поділ | 557 train / 186 validation / 186 test, без перетину пацієнтів |
| Пул зображень | 64 патчі 256 × 256 пікселів на пацієнта; загалом 59 456 |
| Навчальні бюджети | 16, 32, 64 патчі на пацієнта за епоху |
| Модель | ResNet18 з агрегацією на основі механізму уваги; спільне навчання енкодера й агрегатора |
| Seed | 20261113, 20261114, 20261115 |
| Основні запуски | 9 |
| Вибір моделі | Мінімальна валідаційна перехресна ентропія |
| Рання зупинка | До 30 епох; patience 5 |
| Оцінювання | Усі 64 патчі без аугментацій |
| Парний аналіз | 10 000 повторних вибірок тестових пацієнтів за фіксованих моделей |

За бюджету 16 модель використовує всі 64 патчі протягом повного чотириепохового циклу. Решта патчів не вилучається з навчання назавжди.

Наявність транскриптомних даних була умовою формування вихідної парної когорти, але ці дані не подавались до моделей цього експерименту.

## Дані та потрібні входи

Вихідні слайди походять із [Genomic Data Commons](https://portal.gdc.cancer.gov/). Для повторення цієї вибірки потрібні зафіксовані ідентифікатори файлів GDC, маніфести, координати патчів і поділ пацієнтів. Довільне повторне завантаження даних тих самих проєктів не гарантує збігу когорти.

Для наведених нижче команд потрібна повна локальна копія матеріалів відповідного етапу:

- скрипти та їхні залежності з оригінальними контрольними сумами;
- маніфести підготовки зображень;
- PNG у `data/tiles/production_final_v2_tissue080/`;
- результати підготовки Stage 28 у `results/wsi_patch_budget_v1/`, зокрема `patient_splits.csv`, `patch_inventory.csv`, протокол і дані перевірки цілісності;
- вихідні ваги ResNet18 та службові матеріали підготовки, які перевіряють скрипти;
- для тестового оцінювання — вибрані моделі та завершені результати дев’яти запусків Stage 31.

Вихідні WSI можна отримувати з GDC за маніфестом; зберігати їх у GitHub не потрібно.

## Основне навчання

Команди виконуються в PowerShell із кореня підготовленого проєкту. Активація середовища не обов’язкова: шлях до його інтерпретатора зазначено явно.

Перевірка основного етапу:

```powershell
.\.venv\Scripts\python.exe -B scripts\31_train_patch_budget_baselines.py --preflight-only
```

Для нової локальної серії до запуску необхідно виконати `--prepare` за наявності всіх потрібних входів. Повторний виклик для вже підготовленої серії перевіряє наявний протокол.

Перший запуск або продовження після переривання:

```powershell
.\.venv\Scripts\python.exe -B scripts\31_train_patch_budget_baselines.py --run --budget 64 --seed 20261113
```

Матриця основних запусків:

```powershell
foreach ($seed in 20261113, 20261114, 20261115) {
    foreach ($budget in 64, 32, 16) {
        .\.venv\Scripts\python.exe -B scripts\31_train_patch_budget_baselines.py --run --budget $budget --seed $seed
        if ($LASTEXITCODE -ne 0) {
            throw "Зупинено через помилку: budget=$budget, seed=$seed"
        }
    }
}
```

Цикл показує склад матриці; фактичну історію вихідних запусків відображають журнали сесій. Повторення тієї самої команди відновлює незавершений запуск із checkpoint. Завершені запуски пропускаються; статус `AMP_SKIPS` потребує окремого розбору.

## Тестове оцінювання

Stage 32 використовує дев’ять моделей, уже вибраних за валідаційною перехресною ентропією. Він не навчає моделі й не вибирає їх за тестовою якістю.

Для повної копії входів Stage 32:

```powershell
.\.venv\Scripts\python.exe -B scripts\32_evaluate_patch_budget_test.py --preflight-only
.\.venv\Scripts\python.exe -B scripts\32_evaluate_patch_budget_test.py --prepare
.\.venv\Scripts\python.exe -B scripts\32_evaluate_patch_budget_test.py --smoke
.\.venv\Scripts\python.exe -B scripts\32_evaluate_patch_budget_test.py --run
```

`--smoke` перевіряє відтворення валідаційних прогнозів. Тестові зображення читає лише `--run`. Після переривання повторюється та сама команда.

Повторний аналіз завершеної матриці тестових прогнозів:

```powershell
.\.venv\Scripts\python.exe -B scripts\32_evaluate_patch_budget_test.py --analyze
```

`--analyze` не повторює навчання чи тестовий інференс, але потребує перевірюваних матеріалів Stage 28/31/32 та залежностей. Один файл `test_predictions.csv` не замінює цей набір.

## Межі відтворення та інтерпретації

Архівні скрипти перевіряють хеші коду, даних, протоколів і параметри середовища. Зокрема, Stage 32 прив’язаний до конкретного протоколу Stage 31. Вони можуть відхилити запуск на іншому комп’ютері або на повторно створеному протоколі; переносимість на довільне середовище не перевірена. Для відтворення в іншому середовищі потрібна документована адаптація зі збереженням вихідного коду й протоколів.

Час і піки пам’яті залежать від обладнання та умов виконання. Публікація коду не гарантує числового збігу часу або побітового збігу на іншому обладнанні.

Висновки стосуються одного пацієнтного поділу, однієї архітектури й трьох seed на бюджет. Режими мають спільне правило зупинки, але різну фактичну кількість епох. Поліпшення якості не можна приписувати винятково регуляризації через семплювання. Економія окремої навчальної епохи не дорівнює економії повного запуску.
